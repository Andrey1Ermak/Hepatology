# Библиотека полных текстов

Здесь собираются полные тексты статей и руководств, которые команда не может открыть сама (платный доступ). Без них числа остаются `TODO(verify)` и не публикуются.

## Что где

| Путь | Что это | В git? |
|---|---|---|
| [`WANTED.md`](WANTED.md) | **Список нужного** — что принести, где взять и зачем. Сверху самое срочное | да |
| `catalog.json` | Реестр (из него собирается WANTED.md) | да |
| `inbox/` | **Сюда класть файлы.** Имя любое | нет |
| `pdf/` | Разобранные PDF, `<id>.pdf` | нет |
| `text/` | Текст, извлечённый из PDF | нет |
| `notes/<id>.md` | Конспект полного текста: числа, критерии, формулировки со ссылкой на страницу и таблицу | да |

Репозиторий публичный, поэтому сами PDF никогда не попадают в git — только на этот Mac. Облачный ежедневный прогон PDF не видит: он работает по **конспектам** из `notes/`. Поэтому путь документа такой:

```
wanted  →  received  →  noted  →  applied
нужен      PDF на Mac   конспект   учтено в карточках
           (inbox/)     в git      (облачный прогон)
```

## Что делать автору

1. Время от времени открыть [`WANTED.md`](WANTED.md) (по воскресеньям сводка есть и в `reports/weekly/`).
2. Скачать что получится (библиотека, членство в обществах, запрос автору статьи) и положить в `library/inbox/`. Переименовывать не нужно.
3. Открыть Claude Code в проекте и написать **`/library`** (или «обработай библиотеку»). Он разложит файлы, напишет конспекты и отправит их в `main`.
4. Всё. Следующий утренний прогон сам внесёт новое в карточки и отметит документ как `applied`.

Можно приносить и то, чего нет в списке, если документ кажется полезным, — Claude сам заведёт запись.

## Как работает команда (кратко; правила — CLAUDE.md §6a)

- **Облачный прогон** заносит документ в `catalog.json` только когда точно определил его (DOI) и не нашёл свободного полного текста (PMC, Europe PMC, сайт журнала, рукопись автора). Раз в неделю `python3 tools/library.py oa-check` проверяет, не открылся ли доступ (рукописи NIH появляются в PMC через 12 месяцев).
- **Сессия на Mac** (`/library`) — единственное место, где читаются PDF: `ingest` → конспект → `set <id> noted` → коммит.
- **Облачный прогон** видит статус `noted`, применяет конспект (закрывает `TODO(verify)`, задачи бэклога, DECISIONS) и ставит `applied`.

## Команды

```bash
python3 tools/library.py              # сводка: что нужно, что в inbox, что ждёт конспекта
python3 tools/library.py ingest       # разложить inbox/ (по DOI на первых страницах или по id в имени файла)
python3 tools/library.py assign inbox/файл.pdf <id>   # вручную, если не распознался
python3 tools/library.py set <id> noted               # после того как написан notes/<id>.md
python3 tools/library.py oa-check     # не стал ли нужный документ бесплатным
python3 tools/library.py render       # пересобрать WANTED.md
python3 tools/library.py check        # проверка целостности (запускается в CI)
```

## Формат конспекта `notes/<id>.md`

Английский, коротко, только факты. Конспект лежит в публичном репозитории, поэтому **без перепечатки текста**: своими словами, точные числа, и не более одной короткой цитаты (< 15 слов) на пункт; таблицы не копировать целиком — только нужные строки и числа.

```markdown
# <id> — full-text note

- **Source:** <citation>, doi:<doi>
- **Read:** YYYY-MM-DD from the full text (<N> pages). Pediatric section: pp. X–Y.
- **Status of document:** guideline / position paper / study; endorsed by …; supersedes …

## Answers to what was needed
<по каждому пункту из "need" в catalog.json: ответ, число, сила рекомендации — (p. 7, Table 2)>
- Not in the text: <что искали, но в документе нет — это тоже ответ>

## Other facts useful for cards
- <card_id>: <fact> (p. N)

## Conflicts with what the app says now
- <card_id / TODO(verify)>: app says X, full text says Y (p. N)
```
